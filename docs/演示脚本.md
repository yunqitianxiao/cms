# 演示脚本

目标：15 分钟内把评分表的每一条都"演"出来，而不是"说"出来。每一幕都写了**操作**和**验收点**，验收点是可以当场失败的。

---

## 准备

```bash
sudo bash db/init.sh          # 建库 + 演示数据
mvn spring-boot:run
```

浏览器打开 http://localhost:8090 ，准备三个窗口（建议一个普通窗口 + 一个无痕窗口，用于演示乐观锁和会话隔离）。

演示账号（密码均 `123456`）：`admin` / `author` / `auditor` / `guest` / `bob`。

---

## 第 1 幕 · 登录与角色裁剪（用户权限管理，2 分）

1. 用 `guest` 登录，指出左侧菜单只有「工作台 / 文章列表 / 分类」。
2. 退出，用 `admin` 登录，菜单多出「内容审核 / 用户管理 / 角色与权限 / 操作日志」。

**验收点**：同一套前端，菜单随角色变化；直接手输 URL 访问 `/app/users` 仍会被后端拦下——刷新后跳回登录或提示无权限，而不是"页面能打开但没数据"。

3. 打开 `author` 的页面，地址栏直接输入 `/api/users`，页面显示 `40300 没有操作权限`。

**验收点**：权限在接口层，不在菜单层。

---

## 第 2 幕 · 作者投稿（文章内容管理，1.5 分）

1. `author` 登录 → 工作台，指出「我的稿件」四个数字来自实时查询。
2. 点「写文章」，填标题、摘要、正文，选三级分类（技术 > 后端 > Java），点「保存并提交审核」。
3. 回到文章列表，新文章状态为「待审核」。

**验收点**：列表里新稿是 PENDING；`sys_log` 里多一条 `ARTICLE / 提交审核 / SUCCESS`。

---

## 第 3 幕 · 审核与状态机（文章内容管理 + 高级数据处理）

1. `auditor` 登录 → 内容审核，只看到待审核稿件。
2. 找到 `author` 刚提交的那篇，点「驳回」，**意见留空** → 提示必须填写。
3. 填「摘要需要补充数据来源」→ 状态变「已驳回」。
4. `author` 登录，列表里能看到审核意见；点编辑修改后保存 → 状态自动回到「草稿」；再提交审核。
5. `auditor` 通过 → 文章立即出现在前台。

**验收点**：
- 驳回空意见被拦（400）；
- 被驳回稿修改后回草稿，而不是直接回待审核；
- 审核员不能审核自己提交的稿（用 `admin` 提交一篇，再用 `admin` 打开审核页，自己的稿子勾选框是禁用的）。

6. 对一篇「已发布」的文章直接调编辑接口（或点在列表里不存在的编辑按钮）→ `40901 当前状态不允许该操作`。

**验收点**：状态机是白名单，不是一串散落的 if。

---

## 第 4 幕 · 下架与重新提交（新增链路）

1. `auditor` 在文章列表对已发布文章点「下架」，填原因。
2. `author` 在列表里看到「已下架」和原因，点「重新提交审核」。
3. 稿件回到「待审核」。

**验收点**：`OFFLINE → PENDING` 这条边真的能走通；开发过程中曾发现 `RESUBMIT` 动作有定义但没有接口使用，属于"状态图上有、代码里没有"的死路，已补接口并演示。

---

## 第 5 幕 · 分类树（内容分类管理，1.5 分）

1. `admin` → 分类管理：三级缩进展示。
2. 在「Java」下点「加子分类」→ 该按钮不出现（已是第 3 级）。

**验收点**：层级上限在界面上就体现，后端仍会返回 `40001`（用 ApiFox 直接调接口验证）。

3. 新建一个分类 → 排序填 1 → 保存，列表顺序变化。
4. 尝试删除「技术」→ 提示有子分类或文章引用，`40903`。

**验收点**：删除保护来自外键 + 服务层翻译，不是前端弹窗拦截。

5. 停用一个空分类，再尝试在该分类下新建文章 → 提示"分类已停用，不能用于发布"。

---

## 第 6 幕 · 用户、角色与权限（2 分里的"授权"部分）

1. `admin` → 用户管理：搜索、按角色筛选、新增账号、停用账号。
2. 停用 `author`，用无痕窗口以 `author` 登录 → `40102 账号已被停用`。
3. 角色与权限：给 `AUTHOR` 取消 `article:create` → 保存。
4. 回到 `author`（无需重新登录）刷新写文章页 → 接口返回 403。

**验收点**：权限缓存随保存失效，不是"重启才生效"。

5. 尝试取消 `ADMIN` 的「角色管理」权限 → `40900`，提示"管理员角色必须保留「角色管理」权限"。

**验收点**：这是一个真实存在的锁死风险——如果允许取消，就再也没人能进权限页把它加回来。

6. 尝试删除 `ADMIN` 角色 → 被拒绝。
7. 删除账号 `author`（初始数据里有他的稿件）→ `40903 该用户名下还有 N 篇稿件`。

**验收点**：用户是逻辑删除，外键拦不住；不显式计数的话，稿件会指向一个"已删除"的作者，列表里作者名空白且再没人能接手编辑。

8. 删除自己（`admin` 这一行）→ 前端直接拦"不能删除自己"，后端同样拒绝；删除最后一个可用管理员同样被拒。

---

## 第 7 幕 · 日志与越权痕迹（系统基础运维，1 分）

1. `admin` → 操作日志，按类型筛「审核」，按结果筛「被拦截（DENIED）」。
2. 能看到前面几次越权尝试：谁、什么接口、什么时间、失败原因。
3. 点开一条登录日志 → 参数里密码显示为 `***`。

**验收点**：`DENIED` 与 `FAIL` 分开统计；敏感字段脱敏。

4. 指出日志切面在权限切面外层（`@Order(1)` vs `@Order(2)`），所以被 403 拦下的请求仍然留痕。

---

## 第 8 幕 · 站内引导智能体（AI 应用，2 分 + 亮点）

这是本项目区别于"又一个 CRUD"的部分，建议给足 4 分钟。

1. 任意账号点右下角悬浮球 → 对话框里立刻出现**全站页面卡片**，按「内容 / 账号与权限 / 系统 / 前台」分组。

**验收点**：卡片不是写死在前端的。打开 `/api/guide/pages` 也能拿到同一份数据——它来自启动时对 `RequestMappingHandlerMapping` 的反射。

2. 输入「我想写一篇新文章」→ 命中「写新文章」卡片。

**验收点**：`source = RULE`，不需要联网、不需要模型。

3. 输入「审核」→ 命中「内容审核」；输入「今天天气怎么样」→ 明确回答"系统里没有这个功能"，不返回任何卡片。

**验收点**：阈值生效，不硬塞。

4. 用 `guest` 打开同一个对话框 → 「用户管理」「角色与权限」「操作日志」卡片置灰，点开说明缺 `user:manage` 等权限。

**验收点**：智能体知道自己"不能去"，不会把用户带到 403 页面。

5. 点「写新文章」卡片 → 跳到编辑页，标题输入框高亮约 5 秒。

**验收点**：卡片里的 `highlight` 选择器真的命中元素。

6. 点右上角 `⚙`：状态显示"使用服务端配置的密钥 sk-…xxxx"（或"规则模式"）。粘贴自己的 DeepSeek key → 保存 → 状态变成"密钥 sk-…yyyy · 仅本次登录有效"；点「测试连接」→ `✓ 连接成功（约 1 秒）`。填一个错的 key 再测 → `✗ 连接失败：401`，界面不崩、日志里也看不到明文。

**验收点**：密钥只存会话；`GET /api/guide/llm` 永远只回尾号。退出重登后 `source` 回到 `CONFIG/NONE`。

7. 问一个规则命不中的问题（如"怎么把账号权限开给别人"）→ 回答来自模型，来源标为 **模型理解（DeepSeek）**，卡片仍然只有 `user.manage` / `role.manage`。

**验收点**：模型只从候选卡片里挑；给规则能命中的问题（如"我想写一篇新文章"）仍显示"规则匹配"，不额外走网络。

8. 讲清边界：没有密钥时模型通道不启用，规则路由完整可用；开启后模型也只返回卡片 id，id 不在站点地图里就丢弃，卡片文案从不经过模型。

## 第 9 幕 · 启动期硬校验（可选，1 分钟）

1. 临时复制一个 Controller，去掉 `@GuideCard` 但保留 `@RequirePermission`，重启。

**验收点**：服务**拒绝启动**，报 `C2 Controller 有 @RequirePermission 但整类没有 @GuideCard`。删掉临时文件恢复。

> 这一条的价值：它把"智能体知道全站"从一句承诺变成了一个会让进程起不来的约束。评审如果只记一件事，记这个。

## 第 10 幕 · MyBatis-Plus 与 SQL 优化（2 分）

1. **乐观锁**：两个窗口同时编辑同一篇草稿，A 先保存，B 后保存 → B 收到「文章已被他人修改，请刷新后重试」。

2. **逻辑删除**：删除一篇草稿，列表消失；用数据库客户端查 `cms_article`，行还在，`deleted = 1`。

3. **防全表更新**：临时调一个没有 where 的 `update`（或在 ApiFox 构造空条件）→ 被 `BlockAttackInnerInterceptor` 拦截。

4. **N+1 优化**：打开 `ArticleMapper.xml` 的 `selectPageVO`，指出分类名和作者名来自同一条 join，而不是循环里逐条查。

5. **EXPLAIN**：分别执行

```sql
EXPLAIN SELECT * FROM cms_article WHERE status='PUBLISHED' AND category_id=4 ORDER BY create_time DESC;
EXPLAIN SELECT * FROM cms_article WHERE title LIKE '%分页%';
```

第一条走 `idx_article_query`；第二条 `type=ALL`——这就是报告里"为什么 `%kw%` 用不上索引"的对照实验。

## 可能被问到的问题

| 问题 | 回答要点 |
|---|---|
| 智能体是不是调大模型？ | 规则命中时不是——L0 是确定性的中文 bigram 匹配，离线可用，也省一次网络往返。规则没命中时才问模型；用户在对话框 `⚙` 里填自己的 key（只存会话），或由服务端配置。模型只负责选卡片 id，不生成页面 |
| 页面加了一个，智能体会不会漏？ | 不会。受控模块整类没有 `@GuideCard` 时服务拒绝启动 |
| 权限为什么不放在前端判断？ | 前端只做"显示/隐藏"，真正的判断在 AOP 切面；手调接口一样会被拦 |
| 为什么不用 JWT？ | 单体同源应用，Session 的"退出即失效"更直接；JWT 要退出就得维护黑名单，等于多一张有状态表 |
| 分类为什么最多 3 级？ | 题面未规定。3 级覆盖真实分类结构，再深会让树渲染和"移动分类"的成本超过收益 |
| 日志为什么不是异步？ | 异步线程池满时丢的正好是故障时的日志；改为 `REQUIRES_NEW` 同步写入，业务回滚日志仍在 |
