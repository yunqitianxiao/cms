## 四、本轮联调发现并修掉的缺陷

这些不是"计划内功能"，是按 `演示脚本.md` 演到那一幕时**失败**才发现的。

| 现象 | 根因 | 修复 |
|---|---|---|
| 8 个数据页全部停在"加载中"，接口本身 200 | 页面模块顶层写了 `await bootReady;`，模块求值挂起在 await，后面的 `const state/COLS` 尚未初始化；恢复执行时 `main()` 读到暂时性死区，控制台报 `can't access lexical declaration 'COLS' before initialization` | 改成 `bootReady.then(...).catch(console.error)`，把启动排到模块求值结束之后（`src/main/resources/static/js/pages/*.js`） |
| 批量通过/下架后弹窗显示"成功"但实际有失败项 | 前端判断 `if (!r.failed)`；`failed` 是**失败 id 数组**，空数组在 JS 里是真值，`reasons` 是对象没有 `.map` | 改成 `failedIds.length` 并逐条渲染 `reasons[id]`；`docs/api.md` 补上"`failed` 是数组不是个数" |
| 停用有启用子分类的父分类居然成功 | 只在删除时做了引用检查，停用路径没有 | `CmsCategoryMapper.countEnabledChildren` + `checkCanDisable`，`update` 与 `updateStatus` 两条路径都走 |
| 日志 `params` 尾巴挂着 `org.apache.catalina.connector.RequestFacade@28ef8fa8` | `MaskUtil` 按类名前缀（`javax.servlet` 等）判断"基础设施对象"，而容器传入的实例类名是 `org.apache.catalina.connector.RequestFacade`，一个前缀都不沾 | 改为 `instanceof javax.servlet.ServletRequest/ServletResponse` 判断 |
| 删除仍有稿件的账号成功，文章指向"已删除"作者 | 用户是逻辑删除，外键不触发 | `UserService.delete` 先 `selectCount(article.authorId)`，非 0 返回 `40903` |
| 对话框里的页面卡片只有 ~106px 宽，两列挤成细条 | `renderCards` 把卡片网格挂在了 `.guide-msg` 上，而后者是 `display:flex`——网格成了气泡的兄弟节点，三者横向排开（气泡 150px + 网格 219px） | 改为挂进 `.bubble-msg` 内部，气泡在含卡片时 `width/max-width:100%`；卡片回到 165px 两列 |
